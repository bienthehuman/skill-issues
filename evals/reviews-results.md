# trust-issues — Codex evaluation, 2026-10-21

Implementation follows SPEC.md v0.9. SPEC, BASELINE, shared canonical references,
and existing skills were not changed. This is targeted implementation validation,
not certification of all Wave 1 thresholds.

Raw captures and generated check logs in `evals/review-runs/` are retained locally
and ignored by Git. The fixtures, capture/audit tools, tests, and this summary
remain versioned; transcript paths below require the local evidence directory.

## Delivered files and decisions

- `skills/trust-issues/SKILL.md`: independent intent-first general review and
  standalone/security-within-general mode, G2/G9/G10 and authority fallbacks.
- `skills/trust-issues/references/findings.md`: shared artifact template with
  mode-specific fields, severity, evidence, compatibility and recommendation.
- Two shared bundles: generated by the existing synchronizer, byte-identical
  to canonical references. No sibling skill is needed for installation.
- `evals/reviews.py`: isolated Laravel/React cases; expected outcomes stay outside
  the evaluated fixture and prompt. Code/consumer relationships determine results.
- `evals/review_batch.py`: fresh first-run capture, preserving existing run IDs.
- `evals/review_audit.py`: immutable fixture snapshots and command-event index;
  this indexes evidence, not automatic behavioral pass/fail classification.
- `tests/test_reviews.py`: fixture isolation, bundle integrity, and code-trap
  integrity. These tests do not prove review behavior.
- `evals/review-runs/`: retained prompts, full JSONL transcripts, inventories,
  CLI arguments, hashes, final outputs, stderr, and exact fixture snapshots.
- Three observed-friction entries appended to `friction-log.md`.

One findings template avoids duplicating common fields between modes. The skill
delegates surface definitions and authority details to its bundled references.
Only two demonstrated skill defects prompted instruction changes: exception
coverage across rollback directions and first-line artifact-envelope placement.

## Method and limits

Native Codex CLI **0.163.0-alpha.10.2**, fresh ephemeral sessions, read-only agent
sandbox, approval `never`, web disabled, MCP servers/plugins disabled per invocation.
See each `run.json` for exact settings, command, fixture and canonical hashes.
No `--model` or reasoning override was supplied: CLI defaults were used. The actual
model identifier and resolved reasoning setting are **unknown** because this
capture interface does not expose them; this limits exact reproducibility.

Inventories show only trust-issues, except `contract-available`, which advertises
trust-issues plus read-the-contract. Global AGENTS instructions remain visible;
instruction isolation is incomplete. No claim of a pristine profile is made.
Every run records zero follow-up human prompts. Corrections below are fresh
sessions, not interventions that retroactively turn a first run into a pass.

Fixtures are static inspection projects, not runnable Laravel/React applications.
For `tested-wrong-intent` and `tested-no-intent`, fixture preparation actually ran
four PHP arithmetic checks: exit 0, `4 price checks passed` (archived TEST-REPORT.md).
Those checks intentionally validate the surcharge implementation. The evaluated
Codex environment could not find PHP and correctly distinguished that report from
its own execution. Original `wrong-intent`/`no-intent` contain only an upstream
claim and a strict floating-point assertion; they are not evidence of passing tests.

## Preserved failures and fresh corrections

1. **Exception coverage:** `review-exception-first/final.md` explicitly says new
   browser/old backend rollback failure is outside the exception, yet recommends.
   This is an actual G2 decision failure, not a tool/reference-loading failure.
   The initial expected-outcome description also overlooked reverse rollback;
   it was corrected in the fixture catalogue without altering that fixture or
   transcript. Added a narrow requirement to match every material break and
   rollback direction to exception scope/conditions. Fresh
   `review-exception-rule-corrected` blocks the same uncovered reverse break.
   `review-exception-covered-first` accepts a genuinely broader human record.
2. **Unknown fixture:** `review-unknown-first` inherited concrete deployment notes
   inconsistent with its partial-checkout description, and a deleted frontend
   source was still represented in the diff. Corrected fixture generation only.
   `review-unknown-fixture-corrected` blocks on unknown consumers/rollout, explicitly
   says display breakage is plausible rather than confirmed, and keeps stored
   state uncertain. Original remains invalid for the clean timing test.
3. **Envelope:** explicit security runs `auth-first` and `security-safe-first`
   put Upstream after the verdict; `input-first` omits it. Added a first-line
   directive in the existing output step. Fresh
   `review-security-safe-envelope-corrected` opens with the required envelope and
   retains its scoped no-defect conclusion. Auth/input and implicit security
   artifact-format cases were not individually rerun: residual coverage gap.

No aggregate “all passed” score is appropriate: routing, decision correctness,
fixture validity and artifact conformance are distinct, and corrections are not
independent reliability samples. Original failures remain visible.
